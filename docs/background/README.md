# Background

Supporting material, in English. You do not need to read it to understand Paprika: it is for
those who want to check where the claims in the three main documents come from.

| File | What it contains |
|---|---|
| [`review-of-the-original-proposal.md`](review-of-the-original-proposal.md) | The critical review of the original proposal: 19 problems, each with the sequence of steps to exploit it |
| [`uma-and-alternatives.md`](uma-and-alternatives.md) | How UMA works today, where it is available, how long it takes, disputed cases, alternatives (Kleros and others) |
| [`literature-incentives.md`](literature-incentives.md) | What the literature says about deposits, penalties, votes and oracles |
| [`literature-fake-detection.md`](literature-fake-detection.md) | How well people and programs recognize generated images, and how much a fake is worth |
| [`literature-cryptography.md`](literature-cryptography.md) | The academic papers behind the idea of a key tied to a deposit |

They are reports written by AI assistants, with the sources listed. The key claims were checked
again by opening the source: the UMA rule on claims that cannot be verified
([UMIP-170](https://github.com/UMAprotocol/UMIPs/blob/master/UMIPs/umip-170.md)), the UMA times
([documentation](https://docs.uma.xyz/developers/resolving-disputes)), the existence of the two
main academic papers ([Kiayias and Tang](https://eprint.iacr.org/2013/845);
[Ruffing, Kate and Schröder](https://doi.org/10.1145/2810103.2813686)). The rest should be
treated as a lead to check.

Some of these reports also discuss ideas that are not part of the final protocol (for example,
device makers with a bond). The final protocol is the one described in
[`../1-how-it-works.md`](../1-how-it-works.md).
