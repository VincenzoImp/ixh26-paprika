## What works (no need to re-test)

- README quick start from the repo root; `npm start`; `npm run stop` (default and per `RPC_PORT`); `npm run demo:cli`.
- Contract suite: 8/8, with the real UMA OOv3 and VotingV2 and WETH9; invariants hold after every test.
- `node cli.js demo`: 13/13 steps, money deltas as documented (accuser −B / +B−fB, depositor +B−fB, Store +fB, refund +B).
- CLI happy paths: register, attest, verify, accuse-commit/reveal, vote true/false, advance, refund, withdraw, revoke, unwrap, balances, status. Refused correctly: reveal without commit, vote without assertion, accuse an unknown photo, refund twice, withdraw with no credit, revoke twice, attest with a revoked or flagged key ("not active"), re-register a revoked key ("key used"), bad arguments for advance/vote/withdraw.
- Web: the whole demo story (e2e, 116 checks). Header balances and credits equal the chain after every step. The measured settle amounts equal the rule. Record and device states match the chain. The challenge period is extended after a rejected vote. Refund works only after `refundableAt`. A revoke moves no money.
- Double clicks on Register, Attest, Commit, Reveal and Vote send only one action (the busy lock works).
- Out-of-order buttons (Reveal, Vote, Verify, Withdraw) are disabled until their step.
- Verify: one pixel changed gives no record. An empty file, a 10 MB file (about 300 ms) and a text file give "No record". A file attested by two devices shows "2 (one per device that signed it)". Refunded gives "unchallenged". Fake, flagged-fake-proven and flagged-key-revoked show correctly.
- The page shows a clear fatal message when the chain is down and when the context is not secure. The chain-dot turns off when the chain stops.
- Layout at 1440, 1280 and 1024: no horizontal scroll, no clipped text (the right column moves below at 1024). Screenshots `explore-width-*.png`.
- Console: no page errors. The only console errors are the expected logs of failed actions and 502s while the chain is down.
- Button labels in `docs/demo.md` match `index.html`.

## e2e test

- File: `app/e2e/demo.e2e.mjs`. It is a plain Node script using `playwright`. It exits 1 on any failed check.
- It starts its own fresh instance (`scripts/start.js` with `RPC_PORT=8645`, `WEB_PORT=5273`; override with `E2E_RPC_PORT` / `E2E_WEB_PORT`), drives Chromium headless (`HEADED=1` to watch), and stops the instance at the end.
- What it covers: register; attest a sample; verify (file input and "Last attested photo") gives attested; one pixel gives no record; accuse (commit, reveal: record accused, OOv3 holds 2B); vote "does not prove" (accuser −B, depositor credit +B−fB, Store +fB, record attested again, window extended, page amounts = rule); withdraw credit; advance time; refund (record refunded, credit +B); verify gives unchallenged; second photo: accuse and vote "proves the fake" (record fake, device flagged with reason fake-proven, accuser +B−fB); attest refused; new key, attest, revoke (flagged with reason key-revoked, no money moved); verify gives flagged-key-revoked. Header balances and credits are compared with `lib/paprika.js` reads at each money step. It also checks for page or console errors and failed requests.
- Result: **116 passed, 0 failed** (about 40 s). Failure screenshots go to `app/output/e2e/fail-*.png`.
- Run: add to `app/package.json` scripts: `"e2e": "node e2e/demo.e2e.mjs"`, then `cd app && npm run e2e`.
- Exploration screenshots: `app/output/e2e/explore-*.png` (the `explore-exc-*` files are timeouts of my first combined script, re-run as separate scenarios).
